## 1. 护栏演示（60 秒）★ 核心

```bash
# ① 正常简历 → ok
curl -s -X POST localhost:8000/resume/agent -H "Content-Type: application/json" \
  -d '{"raw_text":"张三，3 年后端经验，会 Go 和 PHP"}' | python -m json.tool | head -6

# ② 相对时间 → needs_review
curl -s -X POST localhost:8000/resume/agent -H "Content-Type: application/json" \
  -d '{"raw_text":"赵六，2016 年入行，去年离职，做后端"}' | python -m json.tool | head -8

# ③ 招聘广告 → needs_review（不是简历）
curl -s -X POST localhost:8000/resume/agent -H "Content-Type: application/json" \
  -d '{"raw_text":"岗位要求 3-5 年经验，会 Go，负责后端开发"}' | python -m json.tool | head -8
```

**讲稿**：
> 「第一条正常通过。
> 第二条『去年离职』—— 模型不知道今天是哪年，它照样能算出一个 9 年，
> **这个数字是错的，但接口是 200**。所以护栏把它降级成 needs_review，交人看。
> 第三条更典型：这不是简历，是招聘广告，模型会把『岗位要求 3-5 年』当成这个人的经历。
> 护栏拦下来，因为**它判断的是原文，不是模型的输出** ——
> 这条我踩过坑：一开始按模型输出判断，同一条输入两次结果不一样。」

**要指出的三个字段**：`status` / `reasons` / `total_cost_yuan`

## 2. 多格式入口（30 秒）

```bash

curl -s -X POST localhost:8000/resume/upload -F "file=@工具/test_files/table_resume.docx" | python -m json.tool | head -8

```

**预期**：
```
docx  → 200，抽到 张伟 / 6 年 / 6 项技能
scan  → 422 {"detail":"这份 PDF 没有文本层（很可能是扫描件/图片），需要 OCR 才能解析…"}
```

**讲稿**：
> 「Word 的工作经历经常在表格里，只遍历 paragraphs 会漏掉一半 —— 实测段落 95 字、表格 116 字。
> 扫描件我选择**明确拒绝**，而不是返回空内容 —— 空内容会让下游以为这份简历是空的。」

## 3. RAG 三档检索（40 秒）★ 选型证据

```bash
.venv/Scripts/python.exe 工具/eval_day13.py 2>/dev/null | tail -8
.venv/Scripts/python.exe 工具/eval_day18.py 2>/dev/null | tail -4
```

**预期**：
```
hybrid  5/8   单题 5ms
weighted 6/8  单题 5ms
rerank  7/8   单题 6849ms
---
chroma vs 手写：一致 8/8
```

**讲稿**：
> 「同一份语料三档方案：等权 5/8、加权 6/8、加 rerank 7/8。
> 但 rerank 单题 6849 毫秒，客户要求 P95 ≤ 1.5 秒 —— 所以在线走加权，离线批量才用 rerank。
> **没有最优方案，只有按场景选。**」

## 4. 换库不换语义（20 秒）

```bash
.venv/Scripts/python.exe 工具/eval_day18.py 2>/dev/null | tail -3
```

**讲稿**：
> 「把 numpy 手写余弦换成 chromadb，8 道题的 top-1 逐题一致 —— 说明没换语义。
> 但延迟反而从 2.5ms 变成 14ms，**慢了 5 倍**，这个我照实写进文档。
> 换库买到的是增量写入、metadata 过滤、向量落盘，不是当前规模的性能。」

## 5. 收尾：三种实现对照（30 秒）

**讲稿**（不跑，直接说数字）：
> 「同一套需求我做了三版：手写、LangChain、Dify。
> 手写镜像 488MB，Dify 13.07GB、15 个容器、启动 4 分钟 —— 差 28 倍。
> Dify 的好处是改一条规则秒级生效，客户业务方可以自己调。
> 复刻的时候还反过来发现手写版一个 bug：招聘要求的拦截条件多写了一个『是学生』，
> 纯招聘广告会被放行 —— **换一种实现复刻，本身就是一次代码 review**。」

## 附录 B：常见翻车与应对（现场自救）

| 现象 | 原因 | 现场说法 / 处理 |
|---|---|---|
| `ModuleNotFoundError: Day8_n3_structured` | 没加 `--app-dir 练习` | 补上重跑，顺带讲这是交付坑 |
| `Event loop is closed` 刷屏 | 老版本脚本调了两次 `asyncio.run()` | 已修；说「这是资源泄漏，脚本里只是噪音，常驻服务里会 OOM」 |
| `AuthenticationError` 后自动切下一家 | 降级链在按设计工作 | 不要说"报错了"，说"这是降级链在触发" |
| RAG 评测数字和文档不一致 | 语料变了（新加文档） | 说明「语料版本 439 chunk，数字必须标版本」 |
| 单题延迟明显偏高 | BGE 模型冷启动 | 先空跑一次再演示 |
| 模型返回空壳 `{}` | 上游偶发 | 现场展示 `needs_review`，正好是护栏的价值 |
