### 2. 新建 `app/pdf_font.py`

**目的**：reportlab 默认字体不含中文，不处理就是一堆方块 ▯▯▯。
必须封成一个函数，后面所有 PDF 代码都只调它，不许各自注册字体。

```python
def get_cjk_font() -> str:
    """返回可用作 Paragraph/Table 的字体名（保持引用不释放）。"""

def register_cjk_font() -> str:
    """注册并返回字体名；重复调用只注册一次。"""
```

**字体优先级（必须按顺序回退，任一步失败自动降级）**：

| 顺序 | 方案 | 说明 |
|---|---|---|
| 1 | `C:\Windows\Fonts\msyh.ttc`（微软雅黑）| `TTFont(name, path, subfontIndex=0)`；`.ttc` 必须带 subfontIndex |
| 2 | `C:\Windows\Fonts\simhei.ttf`（黑体）| 单文件 ttf，最稳 |
| 3 | `STSong-Light` | reportlab 内置 CID 字体，`UnicodeCIDFont('STSong-Light')`，**不需要字体文件** |
| 4 | 全失败 | 抛 `RuntimeError("没有可用的中文字体")`，**不许静默用 Helvetica** |

**硬性要求**：
- 必须提供 `font_exists(name) -> bool` 之类的自查能力，或返回时打印实际用了哪套字体
- 字体的 `pdfmetrics.registerFont` 只做一次（模块级缓存，避免重复注册报错）
- 加粗场景：CID 字体没有 bold，用回退（不加粗）而不是抛错

class MatchScore(BaseModel):
    total: int

    category: str                      # language/framework/middleware/db/cloud/tool/domain

class Deduction(BaseModel):

## 六、卡住怎么办

| 现象 | 处理 |
|---|---|
| `TTFont` 读 `.ttc` 报错 | 换 `simhei.ttf`（单文件）；再不行用 `UnicodeCIDFont('STSong-Light')` |
| 装 chromadb 超时 | 先装精简集（见第二节），chromadb 留到 S7 前 |
| pdfplumber 读回是乱码 | 说明字体没真正嵌入 → 检查是否用了 `canvas.setFont` 而不是只在 Paragraph 里指定 |
| 字体名冲突（重复注册） | 模块级 `_registered = None` 缓存，注册一次即可 |
