## 一、本块范围（只做这 4 件）

### 1. `app/schemas_match.py` 追加 `JobInfo`（**只追加，不改已有 5 个模型**）

```python
class JobInfo(BaseModel):
    title: str | None              # 岗位名，如「后端开发工程师」
    company: str | None            # 公司名（JD 没写就 None）
    required_years_min: float | None   # 要求年限下限；写「3-5 年」→ 3
    required_years_max: float | None   # 要求年限上限；写「3-5 年」→ 5；写「3 年以上」→ None
    education: str | None          # 学历要求原文，如「本科及以上」
    must_have: list[str]           # 必备技能，必须是具体技术名词
    nice_to_have: list[str]        # 加分技能
    responsibilities: list[str]    # 职责要点，一条一句
```

要求：中文注释 + `Field(description=...)`；`required_years_min` / `max` 用 `float`（见年限规则）。

### 2. `app/prompts.py` 追加 `SYSTEM_JOB`

要求（写进 prompt 的硬规则）：

```
① 你是岗位信息抽取器，只输出一个 JSON 对象
② 只允许 8 个顶层字段（上面那 8 个），不许自创
③ skills 只收具体技术名词（语言/框架/中间件/数据库/云/工具）；
   「后端」「前端」「全栈」「开发」「工程师」「程序员」「运维」「测试」「架构」
   这类岗位方向词不算技能，不许写进 must_have / nice_to_have
④ 年限规则：
   「3-5 年」→ min=3, max=5
   「3 年以上」→ min=3, max=null
   「不超过 5 年」→ min=null, max=5
   没写年限 → 两个都 null，不许填 0
⑤ 原文没提的字段一律 null / 空数组，不许猜
⑥ 输出示例（few-shot）：
   输入：招聘后端开发工程师，要求 3-5 年经验，熟悉 Go 与 MySQL，了解 Redis 优先，
        负责订单系统的接口开发与性能优化。
   输出：{"title":"后端开发工程师","company":null,"required_years_min":3,
          "required_years_max":5,"education":null,"must_have":["Go","MySQL"],
          "nice_to_have":["Redis"],"responsibilities":["订单系统的接口开发","性能优化"]}
```

## 二、验收判据

| # | 判据 | 怎么看 |
|---|---|---|
| 1 | 3 段真实 JD 抽取字段合理 | 人工看输出：must_have 是具体技术、年限没被写成 0、职责是句子不是关键词堆 |

| 4 | 不许返回空壳当成功 | JSON 解析失败必须抛异常 → failed |
| 5 | 注释 ≥15%、docstring 覆盖 100%（红线 ⑧） | 脚本统计 |

## 六、卡住怎么办

| 现象 | 处理 |
|---|---|
| 模型返回的 JSON 带 ```json 包裹 | 解析前先剥代码块标记（参考 rag.py 的老做法） |

| 成本超 0.002 | JD 一般 300-800 字，超了说明 prompt 太长，先看 usage 再优化 |
